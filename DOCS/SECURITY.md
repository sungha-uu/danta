# 비밀정보와 접근 통제

## 보호 대상

- KIS 모의·실전 App Key와 App Secret
- KIS REST 접근토큰과 WebSocket 접속키
- KIS 실전·모의 계좌번호, 상품코드, HTS ID
- DART API Key와 KRX 인증정보
- SMTP 사용자명·비밀번호·앱 비밀번호
- AI 공급자 API Key
- GitHub 배포 토큰
- 사용자 이메일과 승인 인증정보

## 저장 원칙

- 로컬 개발은 `.secrets/` 또는 OS 자격증명 저장소를 사용한다.
- 운영은 환경변수 주입 또는 전용 비밀 저장소를 사용한다.
- `.env.example`에는 이름과 비민감 기본값만 둔다.
- 실제 값이 있는 `.env`, `.secrets/`, 키 다운로드 파일은 Git에서 제외한다.
- 모의와 실전 키는 파일·프로세스·DB·로그에서 분리한다.
- App Secret과 토큰을 데이터베이스에 평문 보존하지 않는다.

## 로그 마스킹

다음 필드는 구조화 로그 직렬화 전에 마스킹한다.

```text
appkey, secretkey, authorization, token, account_number,
password, smtp_password, api_key, approval_auth
```

계좌 표시는 별칭 또는 끝 4자리만 허용한다. HTTP 요청 전체 헤더나 비밀 파일 내용을 디버그 로그에 남기지 않는다.

## GitHub 경계

- Pages 산출물에는 후보 공개 필드만 포함한다.
- GitHub Actions가 주문 API나 실계좌 키에 접근하지 않게 한다.
- Pages 배포 토큰과 코드 체크아웃 권한은 최소화한다.
- PR·Issue·Artifacts에 실계좌 응답 원문을 첨부하지 않는다.
- 커밋 전 비밀 패턴 검사를 실행한다.

## 주문 권한

- 읽기·분석 프로세스와 주문 프로세스의 자격증명을 가능한 범위에서 분리한다.
- 실전 주문 기능은 환경 배지, 계좌 별칭, 사용자 승인 게이트를 모두 통과해야 한다.
- 승인 ID는 일회용이며 만료시간과 최대 주문 범위를 가진다.
- 위험을 늘리는 매수는 사용자 승인 필요, 위험을 줄이는 보호 매도는 사전 정책으로 자동 허용한다.
- 대시보드 코멘트와 `ENTRY_MANDATE` 권한을 분리하고, Codex 원격 진입 위임에는 지시 ID·nonce·만료·감사 로그를 적용한다.
- GitHub Pages 코멘트, GitHub Issue, 이메일은 그 자체로 주문 명령이 아니다. Android Codex의 사용자 지시를 PC 에이전트가 검증·정규화한 뒤에만 로컬 명령이 된다.
- 로컬 제어 API는 기본적으로 loopback에만 바인딩하고 외부 인터넷에 직접 공개하지 않는다.

## 키 수명주기

1. 발급 즉시 안전한 위치에 저장한다.
2. 모의에서 먼저 검증한다.
3. 노출 의심 시 즉시 폐기·재발급한다.
4. 담당 호스트나 계좌 연결이 바뀌면 KIS 서비스 신청 상태와 자격증명을 재확인한다.
5. 사용하지 않는 키와 토큰 캐시를 제거한다.
6. 키 교체 후 인증·조회·주문 모의 테스트를 다시 수행한다.

## 사고 대응

- 비밀 노출: 키 폐기·재발급, 토큰 무효화, Git 기록 노출 범위 조사
- 계좌 오주문: 신규매수 킬스위치, 미체결 취소, 잔고 대조, 필요 시 사용자 승인 전량 청산
- GitHub Pages 유출: 배포 중단, 공개 산출물 삭제, 노출 키 폐기, 원인 기록
- 승인 위조 의심: 승인 채널 중단, 주문 차단, 감사 로그 보존
