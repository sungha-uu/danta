# AI 에이전트 작업 기준과 문서 인덱스

- 상태: 활성 최상위 기준
- 활성 브로커: 한국투자증권 Open API(KIS)
- 문서 구조: 15개 카테고리, 15개 활성 기준 문서
- 갱신 기준일: 2026-08-05
- 운용 단계: `PAPER_ACTIVE` — KIS 모의투자 사용자 승인형 자동매수·자동매도 허용, 실계좌 잠금 유지

## 1. 프로젝트 정의

튼튼하고 거래 가능한 KOSPI 종목을 먼저 걸러낸 뒤, 최근 하단 접촉 후 실제 `+10%` 도달 경험이 있고 선택 기간 전체에서 현재 다시 하단에 있으며 외국인·기관 자금이 유입되는 숨은 반등 후보를 발굴한다. 활성 박스는 최근 가격 레짐을 분리하는 내부 연구 도구이며 후보 자격·순위·현재 위치·`+10%` 자격을 대체하지 않는다. 사용자가 선택한 1~3개를 실시간 감시하며 사용자 승인형 매수와 자동 손절·적응형 익절을 수행한다.

재무정보는 `financial_statement_analysis-main` 산출물에 의존하지 않고 Danta가 Open DART에서 최소 항목을 직접 수집한다. 매 거래일 16:00에 당일 데이터 완성도를 확인한 뒤 재무 스냅샷·후보·AI 검토·정적 대시보드를 갱신하며, 미완성 데이터나 배포 실패가 있으면 기존 Pages를 보존한다.

운영 구성은 번호로 관리한다. `1 통합 운영·안전 코어`, `2 시장 센싱`,
`3 자율매매`, `4 단기 후보 대시보드`, `5 KOSPI 시장·자금 흐름 대시보드`,
`6 공개용 자율매매 실적 대시보드`이며 상세 정의는
[`PRODUCT_AND_WORKFLOW.md`](PRODUCT_AND_WORKFLOW.md)의 번호 체계를 따른다.

## 4. 변경 불가능한 규칙

- 1순위 주문 연동은 한국투자증권 Open API(KIS)만 사용한다.
- 키움증권 REST API는 비교·향후 대체 어댑터 후보로만 관리하며, 사용자가 다시 전환 승인하기 전에는 주문 공급자로 쓰지 않는다.
- 분봉 수집 유니버스는 거래 가능한 KOSPI 보통주를 시가총액 내림차순으로 정렬한 상위 200개인 `kospi-market-cap-top200-v1`이다. 우선주·ETF·ETN·스팩과 확인 가능한 거래정지·관리·상장폐지 위험 종목은 제외한다.
- 파이썬 정량 엔진은 상위 200개 전부의 7·14·21거래일 1분봉에서 비중복 상승 구간을 계산한다. 1차 순위는 `6% 이상 반복 상승 횟수 내림차순 → 평균 반복 상승폭 내림차순 → 평균 6% 도달시간 오름차순`의 단순 정렬이며 복합 가중치와 좋은 눌림·구조적 붕괴 점수를 사용하지 않는다.
- 내부 계산군인 시총 상위 200개 전부를 공식 주문 후보로 취급하고 대시보드 선택을 허용한다. 14일 기준 현재 박스 하단 35% 이내 여부와 하단 접촉 후 3거래일 안의 실제 +10% 도달 이력은 추천·위험 분석 정보로 유지하되 선택 권한을 잠그지 않는다.
- GitHub Pages에는 시총 상위 200개를 모두 표시한다. 14일 정량 순위 상위 50개만 뉴스·공시·토론·수급 AI 심층검토를 수행하고, 51~200위는 정량 데이터와 `AI 심층검토 대상 외` 상태만 표시한다.
- 화면에 표시되는 시가총액 상위 200개는 모두 `공식 주문 후보`이며 선택·`ENTRY_MANDATE` 생성이 가능하다. 한 승인문에서 사용자가 선택할 수 있는 종목 수는 기존과 같이 최대 3개다.
- 7·14·21일 탭은 14일 기준 200개 순서를 유지한다. 탭 전환 시 반복 상승폭·횟수·도달시간, 가격·수급과 등급·코멘트만 해당 기간 값으로 바꾸며 행을 재정렬하지 않는다. 종목명·코드 검색은 표시된 200개 전체에 적용한다.
- 사용자 대시보드 표의 열 추가·삭제·명칭 변경은 사용자의 명시적 승인 없이는 금지한다. 내부 계산값·검증값은 보고서 DTO·로그·AI 근거에 보존하되 에이전트 판단만으로 사용자 표에 새 열을 노출하지 않는다.
- 반복 상승폭·반복 횟수·6% 도달시간과 박스·현재가의 기간 고점까지 가격 공간·하단 방향 같은 구조 지표의 기준 원본은 `1분봉 OHLCV`다. 확대 차트의 기본 표시봉은 원본에서 재현한 `60분봉 OHLCV`이며 일봉 종가로 대체하는 것은 금지한다.
- `60분봉`은 현재 기준판이고 `30분봉·10분봉`은 성과 개선 실험판이다. 같은 1분봉 원본으로 검증한 뒤 사용자 승인과 전략 버전 승격 없이는 운영 기준봉을 바꾸지 않는다.
- 최초 분봉 수집은 `kospi-market-cap-top200-v1` 전체의 최근 21거래일을 백필하고 이후 매일 완성된 1거래일 증가분을 누적한다. 7·14·21일 중 분봉이 부족한 구조 필드만 `WARMING_UP` 처리한다.
- 사전필터 신규 편입 종목은 고정 7일이 아니라 시스템 공통 수집 시작일부터 현재까지 누락된 거래일을 따라잡고, 완료 전에는 구조 후보·집중 감시·진입 승인 대상이 될 수 없다.
- 사용자가 1~3개를 지정하기 전에는 집중 감시하지 않는다.
- 기본 경로에서 사용자 승인 없는 자율 매수와 물타기는 금지한다. 다만 사용자가
  명시적으로 승인한 `PAPER_AUTONOMOUS_CAMPAIGN`은 승인 시점부터 최대 90일 동안
  KIS 모의계좌에서만 종목별 재승인 없는 신규매수를 허용한다. 실계좌에서는
  설정과 무관하게 거부하고 캠페인에서도 물타기는 금지한다.
- 모의 자율 캠페인은 심층검토 `STRONG_RECOMMEND`·`RECOMMEND` 후보, 계좌 전체
  최대 동시 3종목, 일일 신규 배치 한도, 시장 위험, 데이터 신선도, 잔고대조,
  로컬 kill switch를 모두 통과해야 한다. 중단·만료 후에도 열린 포지션 보호와
  자동매도는 전량 청산까지 유지한다.
- 모의 자율매매의 최초 원금과 누적 성과 기준은 `50,000,000원` 하나다. 사용자
  종목별 승인형 모의운용과 이후 자율 캠페인을 같은 연속 운용으로 취급하며,
  캠페인 승인 시점의 계좌 평가액을 별도 기준자산으로 만들거나 병기하지 않는다.
- 사용자가 대시보드에서 1~3개 종목과 진입 목표가를 정하고 생성된 `ENTRY_MANDATE` 승인문을 Android Codex에 붙여넣으면 현재 잠긴 계좌 모드에서 자동 진입 위임이 성립한다.
- 진입 목표가는 즉시 체결 명령이 아니라 절대 초과할 수 없는 최대 매수가다. 가격 도달 뒤 매도 압력이 강하면 기다리고 하락 안정·매수세 회복이 확인된 때에만 같은 가격 이하의 지정가로 매수한다. 진입 중 박스 하단 이탈은 참고 신호일 뿐 승인을 취소하지 않으며, 사용자 취소·시장 안전 차단·데이터 또는 계좌 무결성 실패 때만 주문을 거두거나 신규매수를 일시 차단한다.
- 다종목 실행은 중앙 `TradingOrchestrator`와 종목별 `SymbolActor`로 분리한다. 현재 사용자 승인 한도는 최대 3개지만 내부 구조는 임의 개수로 확장 가능해야 하며, 종목 워커는 주문을 직접 제출하지 않는다. 중앙 코어도 `-7%` 강제 손절을 거부하거나 지연할 수 없다.
- 주문가능현금 배정률은 1종목 100.0%, 2종목 각 50.0%, 3종목 각 33.3%를 기본값으로 자동 입력하되 사용자가 종목별 비율을 소수점 한 자리까지 수정할 수 있다. 합계는 100% 이하여야 하며 3종목 기본값의 미배정 0.1%를 포함한 잔여분은 현금으로 유지한다. 실제 수량은 KIS 주문가능현금·호가단위·비용을 반영한 최대 정수 수량이다.
- 종목 선택·목표가 입력만으로는 진입 위임이 성립하지 않으며 `ENTRY_MANDATE` 승인문을 Codex에 전달해야 한다.
- GitHub Pages 코멘트는 분석 메모이며, Android Codex의 사용자 지시를 PC 에이전트가 확인한 뒤에만 로컬 작업을 시작한다.
- 평균 체결가 대비 -7%에서 사용자 재확인 없이 전량 시장가 손절한다.
- 익절에는 고정 불변 수익률을 두지 않는다. AI가 모의투자 성과를 분석해 버전된 적응형 수익관리 로직을 제안하고, 승인된 로컬 엔진이 매수세·수급·1분·5분봉·박스 무효화·시장 위험으로 보유 연장 또는 청산을 판단한다. 어떤 익절 버전도 -7% 손절을 취소하거나 지연할 수 없다.
- 비밀, 계좌 식별자, 증권사 식별자, 주문번호, 승인문, 주문가능현금과 원본 KIS
  응답을 GitHub Pages에 게시하지 않는다. 사용자가 공개를 승인한 최초 투자금,
  현재 투자금, 수익률과 정제된 매수·매도 이력은 공개 전용 화이트리스트 DTO와
  비밀 패턴 검사를 통과한 경우에만 6번 실적 Pages에 게시할 수 있다.
- 모의·소액·장애 검증 전 실계좌 주문을 활성화하지 않는다.
- 2026-07-28 모의투자 사전 보증과 KIS 실연결 진단을 통과했으므로 `paper_order_execution_enabled=true`를 활성 기준으로 사용한다. 대시보드는 모의 주문 후보 선택과 `ENTRY_MANDATE` 생성만 허용하며, 실제 주문은 사용자가 승인문을 Codex에 전달하고 로컬 실행기가 `--execute` 이중 게이트를 통과한 뒤에만 제출한다.
- 시장 센싱이 `RISK_OFF/PANIC` 또는 공급자 불완전을 확정하면 신규매수 잠금을
  영속 저장한다. 시장 상태가 `NORMAL`로 회복돼도 잠금은 자동 해제하지 않으며,
  사용자가 시장 상태를 확인하고 명시적으로 재개해야 한다. 잠금 중에도 열린
  포지션의 손절·익절·잔고 대조와 매도 알림은 계속한다.
- 문제를 해결하며 코드·설정·운영절차를 변경하면 트러블슈팅 기록을 남긴다.
- 장애·시장위험 모드에서도 보유 포지션의 보호 감시와 자동 손절은 중단하지 않는다.
- 자동매매 감시는 정규장용·NXT용 별도 운영 프로세스로 나누지 않는다. 하나의
  장기 실행 `UnifiedTradingMonitor`가 KST 거래 세션을 판별해 KRX·NXT·KRX
  예상체결가 입력을 전환하며, 같은 종목 상태·포지션 세대·주문 큐·멱등키를
  계속 사용한다. 휴장·야간에는 주문을 만들지 않고 heartbeat·잔고 복구 준비
  상태로 대기한다.
- 통합 자동매매 런타임의 모든 시작은 `BOOTING -> RECOVERING ->
  RECONCILING`을 반드시 거친다. 사용자는 일반 시작과 복구 시작을 구분하지
  않는다. 복구 대상이 없으면 `IDLE`, 일치하면 기존 작업을 이어서 `RUNNING`,
  모호하거나 불일치하면 신규매수만 막는 `ENTRY_BLOCKED`로 전환한다.
- 런타임은 특정 승인문 파일의 수명에 종속되지 않는다. 주문이 없어도 계속
  실행하며 비공개 명령 inbox의 원자적으로 작성 완료된 `ENTRY_MANDATE`를
  이벤트 감지와 5초 안전 폴링으로 수신한다. 승인문은 삭제하지 않고
  `ACTIVE -> COMPLETED/CANCELLED/REJECTED` 상태로 보관한다. 실제 복구의
  권위 원본은 KIS 잔고·주문·체결과 로컬 DB이며 승인문 파일만 믿지 않는다.
- Codex Plus 사용량과 자동화용 AI API 사용량을 별도 예산으로 관리한다.
- AI 예산 부족은 후보 AI 검토·뉴스 요약·사후 분석을 축소할 수 있지만 로컬 손절·익절·잔고대조를 중단시킬 수 없다.
- 모든 Python 자동화 모듈은 [`QUALITY_AND_VALIDATION.md`](QUALITY_AND_VALIDATION.md)의 관련 체크와 증거를 갖춰야 완료다.
- 실전 전환 후에도 `LIVE_CHAMPION`, `PAPER_SHADOW`, `PAPER_CHALLENGER`를 분리해 모의 검증을 계속한다.
- 매 거래일 점검하되 성과에 따라 실전 알고리즘을 매일 자동 수정하지 않는다.
- 추천·적극추천 로직의 변경을 검토하기 전
  `data/recommendation-performance/latest-summary.json`과 해당 날짜의 동결된
  상위 50개 스냅샷을 확인한다. `INSUFFICIENT_SAMPLE`이면 추천 범위를
  확대하거나 임계값을 완화하지 않고 현행 보수 기준을 유지한다.
- 전략·주문·위험 변경은 개선판으로 검증하고 사용자 승인 후 실전 안정판으로 승격한다.
- 치명 품질 점검 실패는 신규매수만 차단하며 기존 포지션의 보호 감시와 자동매도는 유지한다.
- 일일 품질 보고와 이메일은 AI 사용 가능 여부와 무관하게 로컬 Python이 생성·발송한다.

## 5. 이 세션의 대화 반영

이 Codex 세션을 제품 의사결정의 주 입력으로 사용한다. 매 요청에서 다음을 수행한다.

1. 새 요구사항, 변경 결정, 단순 질문, 아이디어를 구분한다.
2. 확정 요구사항이면 관련 기준 문서를 찾는다.
3. 코드보다 먼저 또는 같은 변경에서 문서를 수정한다.
4. 충돌하는 과거 문장·설정·예시를 함께 수정하거나 삭제한다.
5. 링크, KIS 기준, 정책 충돌을 검사한다.
6. 문제 해결 변경이면 트러블슈팅 기록을 추가하거나 갱신한다.
7. 변경한 문서를 사용자에게 짧게 보고한다.

대화를 그대로 복사하지 않고 구현 가능한 결정·이유·안전제약·TBD만 압축한다. 승인되지 않은 아이디어는 불변 규칙으로 기록하지 않는다.

## 6. 문서 관리

- 새 파일보다 기존 기준 문서 수정을 우선한다.
- 독립된 소유권과 변경주기가 없으면 새 문서를 만들지 않는다.
- 같은 정의는 한 문서에만 두고 다른 문서는 링크한다.
- 구현과 어긋난 문서는 즉시 갱신한다.
- 역사적 가치가 있으면 `ARCHIVE.md`에 기록하고 원본만 보관하며, 가치가 없으면 삭제한다.
- 문서를 추가·제거하면 이 인덱스를 함께 수정한다.

다음 시점에 중복·고아·끊어진 링크·키움 활성 표현 잔존·TBD 우회·코드 불일치를 감사한다.

- 주문·위험 규칙 변경
- 증권사·데이터 공급자 변경
- 개발 Phase 완료
- 실계좌 승격 전
- 문서가 다시 늘어날 때

## 7. 버전과 완료 정의

- 후보 산식: `calculation_version`, `source_bar_interval=1m`, `analysis_bar_interval`
- AI 검토: `model_id`, `prompt_version`, 입력 해시
- 익절: `profit_engine_version`
- 성과 실험: `experiment_id`, 기준판·개선판 버전, 데이터 구간, 비용 가정, 승인 상태
- 외부 API: `provider_capability_snapshot`, 공식 문서 확인일

기능은 코드, 정상·경계·장애 테스트, 설정, 로그·메트릭, 문서, 모의 검증, 품질 체크 증거가 모두 있어야 완료다. 미정 값은 숨기지 않고 `TBD`로 남기며 실계좌에서는 시작을 차단한다.
