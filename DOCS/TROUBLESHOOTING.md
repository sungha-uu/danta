# 트러블슈팅과 장애 학습 기록

## 2026-08-06 실계좌 전환 다음 날 종목·지정가·매수 메일이 모두 없었음

- 증상: 실계좌 런타임은 `RUNNING`이지만 정규장 시작 뒤에도 종목 선정, 지정가격,
  자동매수 메일과 주문이 전혀 생성되지 않았다.
- 직접 원인: 오전 05:30 KST 장외 시장 전체 데이터 조회의 `ValueError`를 시장 비상과
  동일하게 처리해 `MARKET_ENTRY_RESUME_REQUIRED`를 영속 생성했다. 정규장에는 실제로
  KOSPI 약세와 외국인 순매도가 이어져 `CAUTION`이었으므로 신규매수 차단 자체는
  안전정책대로였지만, 자동매매 보류 사유를 메일로 알리는 경로가 없었다.
- 해결: 장외·휴장 시장 데이터 공백은 감사 로그만 남기고 영구 잠금을 만들지 않는다.
  정규장 센싱 오류와 확정 위험만 잠금을 만들며, 시장 때문에 자율 진입이 막히면
  거래일당 한 번 `자율매매 신규진입 보류.` 메일을 발송한다. 종목 선정 메일 제목의
  과거 `모의투자` 표현도 제거한다.
- 검증: 05:30 오류는 잠금 미생성, 정규장 오류는 잠금 생성, 동일 거래일 반복 보류는
  메일 1회, 정상 시장에서는 종목 선정→지정가 메일 순서를 각각 회귀 테스트한다.
- 재발 방지: 시장 데이터 오류를 세션 단계와 분리하지 않은 채 `RISK_OFF`로 승격하지
  않으며, 주문 부재가 정상 안전 차단이어도 사용자에게 자동매매 상태를 설명한다.

### 같은 재기동에서 발견된 시장 센싱 초기화 경쟁

- 증상: 잘못된 잠금을 해제하고 런타임을 재기동하자 시장 첫 표본은 `CAUTION`이었지만
  자율 후보 3개가 먼저 승인되어 실계좌에서 전부 체결됐다.
- 원인: 거래 코어의 시장 위험 기본값이 `NORMAL`이었고, 자율 캠페인이 시장 센싱
  첫 표본 완료 전에 이를 실제 정상 판정으로 오해했다. 후보의 실시간 시세를 순차
  조회하는 동안 시장 상태가 `CAUTION`으로 바뀌어도 주문함 제출 직전 재검증이 없었다.
- 해결: 시장 가드에 `initialized=false` 시작 상태를 추가하고 첫 유효 표본 전에는
  신규 후보 생성을 금지한다. 후보 시세 수집과 배정 계산이 끝난 뒤 주문함 제출 직전
  시장 상태·래치·계좌 상태를 다시 검사한다.
- 검증: 시작 직후 시장 표본 없음, 후보 조회 도중 `NORMAL→CAUTION`, 제출 직전
  래치 생성 세 경우 모두 명령·주문 0건이어야 한다.

## 2026-08-05 자율매매 기준자산이 최초 원금이 아닌 캠페인 승인시점 자산으로 표시됨

- 증상: 최초 모의투자 원금은 50,000,000원이지만 일일 보고서가 2026-07-31
  순자산 53,197,151원을 “캠페인 기준 순자산”으로 표시해 전체 성과를 -0.88%로
  오해하게 했다.
- 원인: 일일 마감 모듈이 첫 실행 시점의 KIS 순자산을 지연 생성 기준값으로
  저장했다. 사용자 승인형 초기 운용과 자율 캠페인을 하나의 연속 검증으로 보는
  제품 정의와 맞지 않았다.
- 해결: 설정의 단일 최초 원금을 50,000,000원으로 고정하고 보고 스키마를 v2로
  변경해 누적손익·누적수익률을 이 원금에서만 계산한다. 기존 보고서도 같은 기준으로
  정정했다.
- 검증: 2026-08-05 순자산 52,728,048원이 누적손익 +2,728,048원,
  누적수익률 +5.46%로 계산되는지 테스트한다.
- 재발 방지: 캠페인 승인시각·평가액을 성과 분모로 자동 생성하지 않는다.

## 2026-08-05 시장 위험 회복 뒤 신규매수가 자동 재개될 수 있던 문제

- 증상: `RISK_OFF/PANIC` 동안 신규매수는 차단됐지만 시장 판단이 `NORMAL`로
  돌아오면 사용자 확인 없이 진입 경로가 다시 열릴 수 있었다.
- 원인: 시장 위험 상태는 메모리의 현재값만 유지했고, 신규진입 중단을 영속하는
  사용자 확인 래치가 없었다. 또한 외국인 5분 증감은 수집·저장만 하고 실제
  위험 판정식에 사용하지 않았다.
- 해결: 위험 확정·시장 데이터 불완전·시장 감시 오류 시
  `private/MARKET_ENTRY_RESUME_REQUIRED`를 원자 생성하고 런타임 재시작 뒤에도
  신규매수만 차단한다. 사용자 `market-entry-gate resume --execute` 뒤에만
  해제하며 위험이 남아 있으면 다음 폴링에서 다시 잠근다.
- 보완: 외국인 5분 급유출 -1,000억원을 주의, -3,000억원과 시장 약세 결합을
  `RISK_OFF` 후보로 반영하는 v3 정책을 추가했다.
- 검증: 위험→정상 전환만으로 매수 의도가 생성되지 않고 명시적 확인 뒤에만
  생성되는 단위 테스트와 위험 중 확인 거부 테스트를 추가한다.
- 재발 방지: 시장 현재상태와 사용자 재개권한을 서로 다른 상태로 관리한다.

## 2026-07-31 코드 교체 직전 구 런타임이 새 자율 배치를 선점한 문제

- 증상: 새 보고서 배치의 지정가격 메일은 발송됐지만 새로 추가한 종목 선정
  메일과 감사 이벤트가 없었다.
- 원인: 낡은 배치의 일일 한도를 되돌린 직후 기존 런타임이 다음 폴링에서 새
  보고서를 먼저 제출했고, 그 뒤에야 새 코드 런타임으로 교체됐다.
- 해결: KIS 보유·미체결과 활성 명령을 대조한 뒤 동일 선택 결과로 누락 메일을
  한 번 복구 발송하고 `OLD_RUNTIME_WON_REPORT_RACE`를 감사 로그에 남겼다.
- 검증: 복구 메일 수신자 2명과 종목 3개를 확인했고 새 런타임 프로세스가
  실행 중임을 확인했다.
- 재발 방지: 자율 캠페인 상태를 수동 복구·초기화할 때는 기존 런타임을 먼저
  중지하고 코드·상태 변경 후 한 번만 재시작한다.

## 2026-07-31 장중 일일 파이프라인이 미완성 당일 분봉을 수집하려 한 문제

- 증상: 16시 이전 수동 `daily-cycle` 실행에서 KRX 거래일 목록의 당일 날짜가
  포함되어 미완성 1분봉 백필을 시작했다.
- 원인: 일일 파이프라인이 KRX 수집기의 `as_of`를 지정하지 않아 시스템 날짜를

- 해결: 16:00 이전 실행은 전일 달력 날짜를 `as_of`로 전달하고, 16:00 이후에만
  당일 날짜를 허용하도록 완료일 경계를 추가했다. 휴일은 KRX가 그 이전 실제
  거래일을 반환한다.
- 검증: 2026-07-31 11:45 KST 입력은 2026-07-30, 16:00 입력은
  2026-07-31을 반환하는 단위 테스트를 추가했다.
- 재발 방지: 자율매매 기준 보고서는 완료 거래일만 허용하며 장중 데이터는
  비공개 KIS 오버레이로만 결합한다.

- 재발 방지: 종목 수 200개 검증은 그대로 유지하되 “상장 200개”가 아니라
  “거래 가능한 시총 상위 200개”를 기준으로 한다.

  `지정가격 산정완료` 메일이 오지 않았다.
- 원인: 기존 메일 큐는 실시간 진입 조건을 모두 통과해 `OrderIntent`가 생기는
  시점에만 연결되어 있었고, 자율 캠페인의 승인문 생성 이벤트에는 연결되지 않았다.
- 해결: 자율 승인문 제출 직후 선택 종목과 최대 매수가를 한 통으로 발송하고,
  SMTP 실패 시 2초·10초 간격으로 최대 3회 시도한 뒤 감사 로그를 남긴다. 실제
  주문 직전 지정가 메일과 체결 메일은 기존 경로를 유지한다.
- 검증: `PAPER_AUTONOMOUS_PRICE_EMAIL_SENT` 감사 이벤트와 수신자 수를 확인한다.
- 재발 방지: 후보 선정 가격, 실제 주문 지정가, 매수 전체체결, 매도 전체체결을
  서로 다른 운영 이벤트로 검사한다.

## 2026-07-31 Windows 종료 프로세스를 활성 런타임으로 오인한 stale lock

- 증상: 런타임 PID를 종료한 뒤 새 `trading-runtime --execute`가 기존 PID가 실행
  중이라며 두 차례 시작을 거부했다. PowerShell/CIM에는 해당 PID가 없었지만
  `OpenProcess`는 종료 객체의 핸들을 잠시 반환했다.
- 원인: Windows 생존 확인이 `OpenProcess` 성공 여부만 검사해 이미 종료되었지만
  커널 객체가 남아 있는 프로세스를 실행 중으로 오인했다.
- 해결: `GetExitCodeProcess`를 추가하고 반환값이 `STILL_ACTIVE(259)`일 때만 실행
  중으로 판정한다.
- 검증: stale PID의 `_process_exists`가 `False`이고 lock을 자동 제거한 뒤 새
  런타임이 복구 단계로 진입하는지 확인한다.
- 재발 방지: lock 파일을 임의 삭제하기 전에 PID, 시작시각, 실제 프로세스 종료
  코드를 함께 확인한다.

## 2026-07-30 시장 상태 메일 중단·자동매매 단계 메일 집중

- 증상: `신규매수 중단 ↔ 정상` 시장 상태 메일이 반복되어 실제 주문 관련
  알림을 확인하기 어려웠다.
- 결정: 시장 상태 수집·위험 게이트·DB·대시보드는 유지하되 시장 전환
  SMTP는 중단한다.
- 해결: 독립 시장 SMTP 실행기를 중지하고 자동매매 메일을 지정가 확정,
  매수 전량 체결, 매도 전량 체결의 세 단계로 제한한다. 매도 메일에는
  평균 매입가 대비 실현수익률을 포함한다.
- 검증: 시장 상태전환은 SMTP 0건, 지정가·매수·매도 각 최종 이벤트는
  멱등키당 1건이며 SMTP 실패 시 최대 3회 재시도해야 한다.

## 2026-07-30 보유 포지션이 있는 주문 실행기 재시작 충돌

- 증상: 알림 코드 적용을 위해 주문 실행기를 재시작했을 때 복원된
  `POSITION_OPEN` 종목을 새 진입 세션으로 다시 등록하려 하면서 실행기가
  안전 종료됐다.
- 원인: 시작 대조는 보유 포지션을 정상 복원했지만 같은 종목이 현재
  `ENTRY_MANDATE`에도 포함된 재시작 경로를 오케스트레이터가 구분하지 않았다.
- 해결: 대조로 복원된 `POSITION_OPEN` 세션은 그대로 유지하고 신규 진입
  재등록을 건너뛴다. 다른 활성 상태의 중복 등록은 계속 거부한다.
- 검증: 보유 포지션과 같은 종목의 위임으로 재시작해도 포지션 세대·수량을

## 2026-07-26 활성 상단 재도달을 +10% 탄력성으로 잘못 대체

- 증상: 최근 실제 최고가가 현재가 또는 박스 하단 대비 `+10%`에 못 미치고 `+10% 도달 0일`인 미스토홀딩스가 7일 후보 3위와 추천 등급으로 표시됐다.
- 원인: 후보 자격과 최종 정렬이 `활성 하단→활성 상단 재도달`을 사용했다. 활성 상단은 최근 고가 90분위 기반이므로 상승폭이 10%보다 작을 수 있는데도, AI 점수는 재도달이 없을 때 최대 69점으로만 제한해 추천 기준 60점을 통과할 수 있었다. 사용자 검토표에도 내부 연구용 활성 구조 네 열을 그대로 노출해 핵심 판단값을 가렸다.
- 해결: 박스 하단 접촉 뒤 3거래일 내 실제 `+10%` 도달 횟수와 기간 실제 최고가의 현재가 `+10%` 도달 여부를 추천 자격과 최종 정렬의 최우선 게이트로 사용한다. 하나라도 미충족한 종목은 비추천으로 제한하고 충족 종목 뒤에만 배치한다. 사용자 표에서는 활성 구조 네 열을 제거하고 진입 기준가·`+10%` 목표가·실제 기간 최고가·`+10%` 이력을 표시한다.
- 검증: 미스토홀딩스의 현재가 44,450원, 현재가 기준 목표 48,895원과 `+10%` 도달 0일을 교차 확인하고, 재산출 뒤 추천 불가·상위 자격군 뒤 배치·실제 Pages 열 표시를 브라우저에서 확인한다.
- 재발 방지: 용어가 비슷한 통계 경계와 투자 목표를 동일 변수로 사용하지 않는다. 목표 수익 자격 테스트에는 목표 가격과 실제 원본 분봉의 순차 도달 증거를 함께 고정한다. 7·14·21일 × 후보 50개 전체를 배포 전 자동 감사하고 위반이 남으면 HTML 생성을 실패시킨다.

## 2026-07-26 기간 하단 대신 활성 위치를 사용한 아모레퍼시픽 오추천

- 증상: 아모레퍼시픽 21일 차트에서 현재가 118,000원이 기간 하단 102,700원보다 크게 높고 하단 기준 +10% 목표가 112,970원도 이미 지났는데 8위 추천으로 표시됐다.
- 원인: 화면의 박스 하단은 21일 기간 박스였지만 `현재 위치`, 후보 자격, 점수와 최종 순위는 최근 레짐으로 다시 계산한 활성 위치 15%를 사용했다. 실제 기간 위치 약 67%가 가려져 서로 다른 박스를 한 행에 섞었다.
- 해결: 후보 자격·점수·등급·순위·화면의 현재 위치를 모두 선택 기간 전체 박스 위치로 통일한다. 활성 위치와 구조 무효화는 내부 연구 산출물에만 남긴다. 하단 기준 +10% 목표가가 현재가 이하이면 이미 진입 시점을 지난 것으로 판정해 추천을 금지한다.
- 검증: 아모레퍼시픽 21일 위치가 기간 박스 기준으로 재계산되고 비추천·후순위가 되는지 확인한다. 7·14·21일 전체 READY 후보에서 표시 위치 재계산, 목표가 선후관계와 추천·순위 불변조건을 자동 감사한다.
- 재발 방지: 한 행에서 박스 경계와 위치의 기준 구간이 다르면 대시보드 생성을 실패시킨다.

## 2026-07-26 KIS 분봉 재수집 중 EGW00201

- 증상: 실제 보고서 재생성 과정에서 KIS 분봉 API가 `EGW00201 초당 거래건수 초과`를 반환해 백필 단계가 중단됐다.
- 원인: 이미 저장된 7일 분봉이 있는 상태에서도 불완전 종목의 누락분을 채우려는 요청이 KIS 호출 제한에 걸렸다.
- 해결: 보고서 산출과 외부 백필을 분리하고 `danta intraday-report --skip-backfill`을 추가했다. 이 옵션은 KRX 기준일과 저장된 1분봉만 읽어 계산하며 KIS 분봉 API를 호출하지 않는다.
- 검증: 저장 분봉 기반 보고서 생성, 전체 테스트, 정적 대시보드 렌더링과 Pages 브라우저 검증을 수행한다.
- 재발 방지: 단순 즉시 재시도를 해결로 간주하지 않는다. 백필은 제한 속도·체크포인트를 따르고, 데이터가 충분한 재계산은 외부 시세 호출과 분리한다.

## 2026-07-26 무효화된 활성 박스의 과대평가

- 증상: 첫 Pages 브라우저 검증에서 현재가가 활성 하단권 아래인 일부 종목이 음수 위치값으로 높은 하단 점수를 받고, 해결 표본 1회의 관측 재도달률 100%로 적극 추천될 수 있었다.
- 원인: 활성 위치 하단 가산에는 하한이 있었지만 현재가와 구조 무효화 가격의 선후관계를 자격 게이트에서 검사하지 않았고, `LOW` 신뢰도에 적극 추천 상한이 없었다.
- 해결: 현재가가 활성 구조 무효화선 아래면 추천 자격을 차단하고 정량 위치 가산을 20%로 감쇠했다. 에이전트 점수는 비추천 구간으로 제한하고, `LOW` 신뢰도는 적극 추천으로 승격하지 않게 했다. 화면 명칭도 `후향 관측 재도달률`로 명확히 했다.
- 검증: 무효화 종목 추천 0개, `LOW` 신뢰 적극 추천 0개를 산출물에서 확인했다. 전체 테스트 68개, Ruff, mypy를 통과하고 Pages의 7·14·21일 각 50행과 차트 팝업을 실제 브라우저에서 확인했다.
- 재발 방지: 낮은 위치를 기회로 가산하기 전에 활성 구조 유효성을 먼저 검사하고, 비율에는 항상 해결 표본과 신뢰도를 함께 노출한다.

## 1. 필수 운영 규칙

문제가 발생하면 임시 우회만 하고 끝내지 않는다. 다음 순서로 처리한다.

1. 피해 확산을 막는다. 주문 관련 문제면 신규매수를 먼저 차단하되 보호 매도는 유지한다.
2. 비밀정보를 노출하지 않고 증상, 환경, 시각, 오류코드, 상관 ID를 수집한다.
3. 재현 가능한 최소 사례를 만든다.
4. 직접 원인과 기여 요인을 구분한다.
5. 코드·설정·운영 절차 중 올바른 위치에서 수정한다.
6. 정상·경계·재발 시나리오 테스트로 해결을 검증한다.
7. 이 문서에 원인, 해결, 검증, 재발방지 조치를 남긴다.
8. 관련 기준 문서와 코드가 어긋났다면 같은 변경에서 갱신한다.

다음 중 하나라도 해당하면 반드시 기록한다.

- 주문·체결·잔고·손절·익절에 영향을 준 문제
- 외부 API의 실제 동작이 문서 또는 예상과 달랐던 문제
- 같은 원인이 반복될 가능성이 있는 문제
- 해결을 위해 코드·설정·운영절차를 변경한 문제
- 데이터 누락·오염·미래정보 누수 가능성이 있었던 문제
- 비밀정보·권한·대시보드 제어 경계 문제

단순 오타처럼 재발 가치가 없는 사항은 기록하지 않는다.

### TS-20260726-001 KIS 모의 REST 호출 제한과 토큰 재발급 충돌

- 상태: RESOLVED
- 심각도: S3
- 환경: paper
- 발생·해결: 2026-07-26
- 영향: `provider-doctor` 잔고 조회 실패, 주문 호출은 없었음
- 탐지: live doctor의 HTTP 실패와 KIS 오류코드 `EGW00201`

#### 증상과 재현

KIS 모의계좌 live doctor에서 토큰과 현재가 요청 뒤 잔고 조회가 실패했다. 진단을 즉시 다시 실행했을 때는 토큰 발급도 HTTP 403으로 거부됐지만 WebSocket 접속키는 발급됐다.

#### 직접 원인

- 모의 REST 현재가와 잔고 요청을 허용 간격 없이 연속 호출해 `EGW00201` 초당 거래건수 초과가 발생했다.
- 프로세스 종료 때 접근토큰을 잃어 진단 재실행마다 토큰을 새로 발급하려 했다.

#### 기여 요인

- 초기 클라이언트에 공급자별 중앙 호출 제한기가 없었다.
- HTTP 오류 응답에서 KIS의 안전한 오류코드·메시지를 보존하지 않아 첫 원인 식별이 늦었다.

#### 즉시 완화

주문을 호출하지 않은 상태에서 진단을 중단하고, 응답의 HTTP 상태와 KIS 오류코드만 출력하도록 분리 진단했다.

#### 영구 해결

- KIS 모의 REST 요청을 `asyncio.Lock`으로 직렬화했다.
- 실측된 모의환경에 최소 1.1초 요청 간격을 적용했다.
- 접근토큰을 Git 제외 비밀 경로에 만료시각과 함께 원자적으로 캐시했다.
- 오류 본문 전체 대신 `msg_cd`, `msg1`만 안전하게 노출하도록 수정했다.
- live doctor 결과를 비민감 capability snapshot으로 저장했다.

1.1초는 2026-07-26 모의환경에서 확인된 현재 완화값이며 영구적인 공식 한도로 간주하지 않는다. `provider-doctor`와 공식 공지에 따라 변경한다.

#### 검증

- Ruff 통과
- Mypy 통과
- 테스트 22개 통과
- 모의 토큰, 삼성전자 현재가, 잔고, WebSocket 접속키 live doctor 전부 통과
- 모의계좌 보유종목 0개 확인
- 주문 호출 0건

#### 재발 방지와 후속 작업

- 모든 KIS REST 호출은 동일한 중앙 제한기를 통과시킨다.
- `EGW00201` 발생 시 즉시 반복하지 않고 지수 백오프와 계측을 적용한다.
- 토큰은 프로세스별로 새로 발급하지 않고 공유 캐시·단일 잠금을 사용한다.
- 향후 다중 프로세스에서는 프로세스 간 분산 제한기와 잠금으로 승격한다.

#### 관련 코드·문서·버전

- `src/danta/adapters/kis/client.py`
- `src/danta/services/provider_doctor.py`
- `data/provider_capability_snapshot.json`

## 2026-07-29 강한 하락장에서 -3%·-5% 조기 방어 미발동

- 증상: 하이닉스·삼성전자·LG전자 모의 포지션이 강한 하락 중 `-3%`와 `-5%`

- 원인 1: 기존 `-5%` 규칙은 절대 방어선이 아니라 매도압력·시장 스트레스 중
  추가 신호를 요구했다.
- 원인 2: `-3%` 방어 점수는 종목 매도압력·약세·시장 스트레스 세 값의 평균인데,
  해당 실행에서 시장 스트레스가 갱신되지 않아 `0`이었다. 그러면 나머지 두 값이
  모두 최대치여도 평균은 `0.667`이고 설정 임계값 `0.72`에 도달할 수 없어
  조기 방어가 구조적으로 발동 불가능했다.
- 해결: 모의 출구 정책을 `exit-defense-profit-paper-v2-minus5-floor`로 올렸다.
  `-5%` 도달은 추가 조건 없이 전량 시장가 청산한다. `-3%`부터는 종목 자체
  매도압력과 약세의 평균 `0.62`, 개별 매도압력 `0.72`, 시장 스트레스 `0.75`
  또는 `RISK_OFF` 중 하나로 전량 조기 청산한다.
- 이중 경로: WebSocket 신호가 없어도 REST 가격 감시가 `-5%`·`-7%` 방어선을
  실행하도록 변경했다.
- 검증: `-5%` 중립 신호 전량 청산, 시장 스트레스 `0`인 `-3%` 강한 로컬 약세
  청산, `-3%` 약한 신호 보유, `-3%` 미도달 보유, REST `-5%` 청산,
  기존 `-7%` 최우선 손절을 회귀 테스트로 고정한다.
- 운영 제한: 정책 변경 후 기존 승인문을 자동 재가동하지 않는다. 열린 포지션이
  없는 상태에서 다음 사용자 `ENTRY_MANDATE`부터 새 정책을 적용한다.

- 원인: `evaluate_exit`가 `strong_loss_pct` 도달 즉시 `HARD_DEFENSE_MINUS_5`를
  반환했으며 회복 신호나 제한 관찰 상태가 없었다. 익절 반납폭도 모든 최고수익

- 해결: `-5%`에서는 데이터 신선도, 시장 비상 아님, 매수회복 점수 `0.72` 이상,

  악화·시간 만료 시 전량매도하도록 변경했다. `-7%`는 예외 없는 독립 강제손절로
  유지했다. 익절은 `+3/+5/+8%` 구간별 반납폭 `1.0/1.5/2.0%p`를 적용했다.
- 검증: 위험 엔진·런타임 핵심 테스트 22개와 전체 테스트 239개가 통과했다. 변경 전

  `010060/322000/475150` 복구, 정책 승인·실계좌 주문 게이트 통과를 확인했다.
- 재발 방지: 위험 단계 추가 시 각 단계의 발동 조건·예외·최대 지연시간을 별도
  테스트한다. 실계좌 정책 파일의 버전을 올리고 재시작 뒤 보유·주문 복구와 활성

- 전일 수급이나 오래된 에이전트 등급만으로는 장중 자율매수를 만들지 않으며,
