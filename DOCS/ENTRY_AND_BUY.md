# 자동매수 알고리즘

## 정규장 신규매수 시간 게이트

- 신규매수 판단과 주문 제출은 평일 KRX 정규장 `09:00 이상 15:30 미만`
  에서만 허용한다.
- 장전 예상체결·NXT·장후 데이터는 진입 참고 신호로만 사용하며 신규매수를
  만들지 않는다.
- 이 시간 게이트는 열린 포지션의 보호 감시와 `-7%` 강제 손절 경로를
  중단하지 않는다.

## 지정가 산정 이메일

- 로컬 진입 엔진이 `SUBMIT_LIMIT_BUY` 주문 의도를 만들고 실제 지정가를
  확정하면 주문 제출 경로를 막지 않는 별도 알림 큐에 이메일을 넣는다.
- 제목은 정확히 `지정가격 산정완료.`로 한다.
- 본문은 `종목명 가격원` 형식으로 종목별 한 줄만 사용한다.
- 같은 주문 의도는 한 번만 알리고, 하락 안정 재대기 후 더 낮은 가격으로
  재산정된 새 주문 의도는 새 가격을 다시 알린다.
- SMTP 실패는 주문·손절 경로를 중단하지 않고 별도 감사 로그와 제한 재시도로
  처리한다.

## 사용자 위임 취소·교체

- 사용자가 목표가가 현재 시장과 지나치게 멀어졌다고 판단하면 미체결 위임을
  취소하고 새 `ENTRY_MANDATE`로 교체할 수 있다.
- 교체 전에 기존 브로커 미체결 주문과 보유 포지션을 대조한다.
- 미체결 주문이 있으면 먼저 취소 확인을 받고, 보유 포지션이 있으면 신규매수
  위임만 중단하며 해당 포지션의 보호·자동매도는 유지한다.
- 기존 위임 종료와 새 위임 활성화는 서로 다른 명령 ID로 감사한다.

- 문서 등급: 활성 진입 기준
- 현재 단계: `entry-stabilization-paper-v1` 모의운용 활성
- 적용 우선순위: 사용자 `ENTRY_MANDATE` 범위 안에서만 동작
- 실시간 실행 주체: 버전이 고정된 로컬 Python 엔진

## 1. 목적

사용자가 승인한 종목을 승인 가격보다 비싸게 추격매수하지 않으면서, 가격 도달 직후 매도 압력이 더 강해지는 낙하 구간을 피하고 하락 둔화·저점 유지·매수세 회복이 확인된 시점에 진입한다.

사용자가 입력한 `entry_target_price_krw`는 **그 가격에 즉시 사라는 체결 명령이 아니라 절대 초과할 수 없는 최대 매수가**다.

현재 승인문의 `entry_trigger: LAST_PRICE_LTE_TARGET` 필드명은 하위 호환을 위해 유지하되 의미는 **가격 자격 게이트가 열림**이다. 이 값만으로 즉시 주문하지 않는다.

- 현재 매도 1호가가 최대 매수가보다 높으면 기다린다.
- 가격이 최대 매수가 이하가 되면 진입 검토 자격만 열린다.
- 매도 압력이 강화 중이면 더 낮은 가격을 기다릴 수 있다.
- 더 낮아졌다는 이유만으로 자동매수하지 않는다. 하락 안정 확인이 필요하다.
- 어떤 판단도 사용자의 최대 매수가보다 비싼 추격매수를 허용하지 않는다.
- 박스 하단 이탈은 참고 정보로만 사용하며 승인 취소 사유가 아니다. 사용자 취소,
  시장 안전 차단, 데이터·계좌 무결성 실패에서는 주문을 거두고 신규매수를 멈춘다.

## 2. 불변 규칙

1. 기본 경로는 유효한 `ENTRY_MANDATE`가 없으면 주문하지 않는다. 예외는 사용자가
   미리 승인한 유효한 `AUTONOMOUS_TRADING_CAMPAIGN`이 생성한 내부
   `ENTRY_MANDATE`이며 현재 KIS 실계좌에서만 허용한다.
2. 승인 종목·계좌 모드·배정률·유효기간을 확대하거나 바꾸지 않는다.
3. 주문 가격은 항상 `entry_target_price_krw` 이하인 지정가다. 시장가 매수와 상한 초과 정정은 금지한다.
4. 사용자가 승인한 주문가능현금 배정액을 초과하지 않는다.
5. 동일 승인·종목의 중복 주문을 멱등키로 차단한다.
6. 물타기와 동일 종목 중복 포지션은 금지한다. 손절 이력만으로 당일 재진입을
   금지하지 않는다. 완전 청산 후 새 포지션 세대를 만들고 현재 가격 할인 폭·장중
   외국인/기관 합산 추정 순매수·반복 상승 여력을 처음부터 다시 통과해야 한다.
7. 부분체결분도 즉시 포지션으로 등록해 `-7%` 보호 감시를 시작한다.
8. 외부 AI 응답을 실시간 주문 경로에서 기다리지 않는다. AI는 사전 정책 제안과 사후 분석만 담당한다.
9. 데이터 지연·호가 이상·KIS 상태 불명·잔고 불일치·시장 위험 모드에서는 신규매수를 차단한다.
10. 정규장 매수부터 검증하며 시간외·동시호가 진입은 별도 승인 전까지 금지한다.

## 3. 상태 머신

| 상태 | 의미 | 다음 동작 |
| --- | --- | --- |
| `UNAUTHORIZED` | 승인문 없음 또는 검증 실패 | 주문 금지 |
| `ARMED_WAIT_PRICE` | 위임은 유효하지만 가격이 상한보다 높음 | 가격 감시 |
| `PRICE_ELIGIBLE` | 현재 매도 1호가가 최대 매수가 이하 | 진입 품질 평가 |
| `FALLING_KNIFE_WAIT` | 매도 압력 강화 또는 시장 위험 | 기다리거나 위임 무효화 |
| `STABILIZING` | 신저가·매도 압력이 둔화되는 중 | 확인 구간 유지 |
| `ENTRY_CONFIRMED` | 안정화와 매수세 회복 조건 충족 | 지정가 주문 의도 생성 |
| `ORDER_SUBMITTED` | 멱등 주문 제출 완료 | 체결·취소 추적 |
| `PARTIALLY_FILLED` | 일부 체결 | 체결분 보호, 잔량 재검증 |
| `FILLED` | 목표 수량 체결 | 자동매도·위험 엔진으로 인계 |
| `INVALIDATED` | 사용자 취소 또는 승인 철회 | 미체결 취소, 신규 주문 금지 |
| `CANCELLED` | 사용자 취소 또는 운영 취소 | 종료 |

가격이 더 내려가도 `FALLING_KNIFE_WAIT`에서 곧바로 `ENTRY_CONFIRMED`로 가지 않는다. 반드시 `STABILIZING`을 거친다.

## 4. 진입 게이트

모든 게이트를 순서대로 통과해야 한다.

### 4.1 승인·계좌 게이트

- 승인 ID, 종목, 최대 매수가, 배정률과 계좌 모드가 유효하다.
- 승인 만료 전이며 사용자가 취소하지 않았다.
- KIS 주문가능현금으로 계산한 수량이 1주 이상이다.
- 동일 종목을 보유하지 않았고 활성 매수 주문도 없다.

### 4.2 시스템·시장 게이트

- 체결·호가·1분봉 데이터가 신선하다.
- KIS 토큰·계좌·주문·조회 경로가 정상이다.
- 잔고 대조와 주문 상태가 일치한다.
- 시장 위험 가드가 `NORMAL` 또는 진입 허용 상태다.
- 장 시작 직후 급락, 변동성 완화장치, 거래정지와 비정상 스프레드에서는 기다린다.

### 4.3 장중 종목 수급 게이트

- 전일 16시 보고서의 7·14·21일 수급은 후보 설명용이며 장중 신규매수 승인에
  단독 사용하지 않는다.
- KIS `종목별 외인기관 추정가집계` 최신 가집계에서 외국인+기관 합산 순매수
  수량이 양수여야 한다.
- 합산 추정 순매수 수량을 당일 누적 거래량으로 나눈 수급강도가 초기 정책
  `0.50%` 이상이어야 한다. 이 기준은 `autonomous-intraday-flow-gated-v3`로
  버전 관리한다.
- 이 값은 연속 실시간 체결값이 아니라 장중 수회 갱신되는 추정치다. 값이 없거나
  오버레이가 신선하지 않으면 자율 신규매수를 차단한다.
- 손절 종목도 이 수급과 가격 안정·매수세 회복을 새로 충족하면 같은 날 다시
  진입할 수 있다. 직전 손절 여부 자체는 점수 가감이나 금지 조건이 아니다.

### 4.4 가격 상한 게이트

```text
best_ask_price <= entry_target_price_krw
limit_order_price <= entry_target_price_krw
```

마지막 체결가만 상한 이하이고 실제 매도 1호가가 상한보다 높으면 주문하지 않는다. 호가단위 정규화 후에도 상한을 넘을 수 없다.

### 4.5 낙하 중 매수 차단

아래 현상을 버전된 시간창에서 조합해 `sell_pressure_score`를 계산한다.

- 매도 주도 체결대금이 10초·30초·1분 구간에서 가속
- 체결강도와 매수 주도 체결 비율이 연속 하락
- 매수호가 잔량 소진, 매도호가 우세와 스프레드 확대
- 1분봉·5분봉 저점과 고점이 연속 하락
- 거래량이 증가하는데 가격 하락이 계속됨
- VWAP 아래에서 회복 실패
- KOSPI·업종 동반 급락

임계값을 넘으면 `FALLING_KNIFE_WAIT`로 전환한다. 정확한 시간창·가중치·임계값은 모의 리플레이 결과 없이 임의 확정하지 않고 전략 버전에 기록한다.

### 4.6 안정화·매수세 회복 확인

다음 중 승인된 정책 버전이 요구하는 조합을 충족해야 한다.

- 일정 시간 또는 봉 수 동안 신저가가 나오지 않음
- 매도 주도 체결대금의 증가가 멈추거나 감소
- 매수호가 잔량이 반복 보강되고 스프레드가 정상화
- 체결강도·매수 주도 체결 비율이 저점에서 회복
- 1분봉 저점이 유지되고 고점·저점 하락이 멈춤
- 단기 VWAP 또는 직전 1분봉 고가를 회복
- 시장·업종 위험 상태가 악화되지 않음

단순히 한 틱 반등하거나 가격이 싸졌다는 이유만으로 진입하지 않는다. `stabilization_score`와 `buy_recovery_score`가 모두 기준을 넘어야 한다.

## 5. 주문과 미체결 처리

```text
allocated_cash = KIS_orderable_cash × allocation_pct / 100
planned_qty = broker_max_buyable_qty(symbol, limit_price, allocated_cash)
limit_price = min(validated_entry_price, entry_target_price_krw)
```

- 상한 이하의 최우선 매도호가를 기준으로 지정가를 만든다.
- 주문 제출 직전 모든 게이트를 다시 검사한다.
- 주문 후 매도 압력이 다시 강화되거나 시장·데이터·계좌 안전조건이 나빠지면
  미체결 잔량을 취소하되 사용자 승인은 유지한다.
- 장중 경과시간만으로 주문을 취소하지 않는다. 주문은 체결되거나 사용자 취소 또는
  시장·데이터·계좌 안전조건 악화가 발생할 때까지 추적한다. 정규장 종료 시에는 당일
  주문을 안전 취소하고 다음 거래일에 처음부터 다시 평가한다.
- 부분체결 상태에서 무효화되면 체결분은 보유 포지션으로 보호하고 잔량만 취소한다.
- 미체결 전량을 취소한 뒤에도 사용자 위임이 유효하면 `WATCHING_ENTRY`로 돌아간다.
  이후 하락 둔화와 매수세 회복을 다시 확인하고, 사용자 최대 매수가 이하의 더 낮은
  최우선 매도호가로 새 주문 시도를 만들 수 있다. 각 시도는 별도 멱등키를 사용한다.
- 거래일 종료로 브로커 주문 수명이 끝나면 다음 거래일에 자동 재제출하지 않는다.
  위임·시장·가격·안정화를 처음부터 다시 검증한다.
- 주문 결과가 불명확하면 KIS 주문·체결 조회로 상태를 확정하기 전에는 재주문하지 않는다.

## 6. 기다림과 무효화의 차이

가격이 상한 아래라는 사실만으로 계속 기다리는 위임을 무기한 유지하지 않는다.

| 상황 | 판단 |
| --- | --- |
| 가격 상한 도달, 매도 압력 강함 | `FALLING_KNIFE_WAIT` |
| 하락 둔화와 매수세 회복 확인 | `ENTRY_CONFIRMED` |
| 최대 매수가보다 다시 상승 | `ARMED_WAIT_PRICE`, 추격 금지 |
| 박스 하단 이탈 | 참고 경고, 승인 유지, 더 낮은 가격에서 안정화 재평가 |
| 시장 위험·데이터 장애·잔고 불일치 | 신규매수 차단, 미체결 취소 |
| 사용자 취소·승인 만료 | `CANCELLED` |

안전 차단선과 다음 거래일 재평가 여부는 승인된 정책 버전에 반드시 포함한다. 장중
경과시간 타임아웃은 취소 사유로 사용하지 않는다. 다음 거래일에는 전일 미체결 주문을
자동 재제출하지 않고 위임·시장·가격·안정화를 처음부터 검증한다.

## 7. 로컬 결정 계약

```python
decision = EntryEngine.evaluate(snapshot, mandate, policy)

# 가능한 결과
WAIT_PRICE
WAIT_SELL_PRESSURE
WAIT_STABILIZATION
SUBMIT_LIMIT_BUY
CANCEL_REMAINDER
INVALIDATE_MANDATE
```

`SUBMIT_LIMIT_BUY`는 종목·수량·지정가·승인 ID·정책 버전·판단 근거를 가진 `EntryIntent`를 반환한다. 도메인 엔진은 KIS를 직접 호출하지 않는다.

| `services/entry_engine.py` | 종목별 상태창, 정책 실행, 재시작 복구 | 브로커 원시 필드 직접 해석 |
| `adapters/kis/realtime.py` | 체결·호가를 내부 스냅샷으로 변환 | 매수 판단 |
| `services/market_regime_guard.py` | 시장·업종 위험과 신규매수 차단 | 매수 주문 직접 제출 |
| `services/order_manager.py` | 멱등 `EntryIntent`, 지정가 주문·정정·취소·체결 대조 | 전략 임계값 변경 |
| `services/entry_replay.py` | 저장된 장중 사례로 정책 버전 비교 | 실계좌 주문 |

자동매수 로직을 후보 선정, 대시보드, 자동매도 코드 안에 섞지 않는다. 자동매수와 자동매도는 `order_manager`와 시장 위험 가드만 공유한다.

## 9. 검증과 개선 지표

모의투자와 리플레이에서 다음을 기준판과 비교한다.

- 최대 매수가 즉시 진입 대비 실제 체결가 개선폭
- 승인 후 체결까지 걸린 시간과 미체결률
- 체결 후 1·5·15·30분 MAE와 MFE
- 낙하 차단으로 피한 손실과 기다리다 놓친 반등
- 잘못된 안정화 신호율과 하락 중 주문 취소·재진입률
- 지정가 슬리피지·부분체결·취소율
- 비용 차감 기대값, Profit Factor, 최대낙폭과 연속손실

성과가 좋아 보여도 표본 수, 상승장·하락장·횡보장 분리, 워크포워드 검증과 장애 시나리오를 통과하기 전에는 실전 안정판으로 승격하지 않는다. 일일 성과에 따라 임계값을 자동 변경하지 않는다.

## 10. 구현 순서

1. `EntryDecision`·상태 머신·최대 매수가 불변조건을 순수 도메인 테스트로 구현
2. 저장된 체결·호가·1분봉으로 `entry-engine-v0` 리플레이
3. 모의투자에서 주문 없이 신호만 기록하는 그림자 모드
4. KIS 모의계좌 지정가 주문·부분체결·취소·재시작 복구 검증
5. 시장 급락·데이터 지연·중복 명령·잔고 불일치 장애 시험
6. 사용자 승인 후에만 모의 자동주문, 이후 소액 실전 후보로 승격

2026-07-28 사전 보증 보고서와 KIS 모의 토큰·현재가·잔고·WebSocket 승인키 진단을 통과해 6단계의 사용자 승인형 모의 자동주문을 시작한다. 대시보드 선택만으로 주문하지 않고 `ENTRY_MANDATE` 전달과 로컬 실행기의 명시적 `--execute`가 모두 필요하다. 실계좌 주문 잠금은 유지한다.

현재 확정되지 않은 것은 매도 압력·안정화 점수의 세부 시간창과 임계값이다. 이 값은 실제 사례 리플레이와 모의투자로 정하며, 확정 전에는 코드 기본값을 임의로 실전 활성화하지 않는다.
