# NXT 익일 보유종목 보호 설계

- 상태: `PAPER_CHALLENGER`
- 활성 증권사: 한국투자증권 Open API(KIS)
- 정책 버전: `premarket-nxt-protection-paper-v1`
- 최종 갱신: 2026-07-28

## 1. 목적과 권한 경계

전일 장 마감 뒤에도 남은 보유종목을 다음 거래일 08시부터 NXT 시세로 관찰하고, 08시 30분 이후 KRX 예상체결가와 결합해 09시 정규장 개시 대응을 미리 준비한다.

이 모듈은 **보유종목 보호 전용**이다.

- 신규매수, 추가매수, 물타기 주문을 만들 수 없다.
- NXT 상승만으로 매수를 제안하거나 승인하지 않는다.
- NXT 약세만으로 `-3%·-5%` 조기매도를 확정하지 않는다.
- 평균 체결가 대비 `-7%`는 기존 절대 손절과 같은 우선순위로 전량 매도 계획을 만든다.
- 실제 주문은 KRX 정규장 주문 가능 시점과 계좌 잔고 재대조 후 기존 `TradingOrchestrator`를 통해서만 제출한다.

## 2. 시간 순서

| KST | 단계 | 동작 |
| --- | --- | --- |
| 07:55 | `RECONCILE` | KIS 잔고·매도가능수량·평균체결가 대조 |
| 08:00~08:50 | `NXT_WATCH` | NXT 체결·10호가를 보유종목에 한해 수집 |
| 08:30~08:50 | `KRX_EXPECTED_OPEN` | KRX 예상체결가를 함께 수집 |
| 08:50~08:59 | `PLAN_LOCK` | 종목별 `HOLD` 또는 `PLAN_FULL_EXIT` 계획 잠금 |
| 09:00~09:05 | `OPENING_RELEASE` | 잔고 재대조 후 기존 주문 큐로 보호 매도 전달 |
| 09:05 이후 | `EXPIRED` | 장전 계획을 폐기하고 장중 위험 엔진으로 이관 |

08:50 이전에는 계획을 잠그지 않고, 09:00 이전에는 KRX 시장가 매도를 제출하지 않는다. 09:05를 넘긴 계획은 재사용하지 않고 반드시 잔고와 시세를 다시 평가한다.

## 3. 공식 KIS 데이터 계약

| 목적 | 거래소 | TR ID |
| --- | --- | --- |
| 실시간 체결 | NXT | `H0NXCNT0` |
| 실시간 10호가 | NXT | `H0NXASP0` |
| 실시간 예상체결 | KRX | `H0STANC0` |
| 실시간 예상체결 | NXT | `H0NXANC0` |
| 현재가 REST 시장 구분 | KRX/NXT/통합 | `J` / `NX` / `UN` |

필드 순서와 TR ID는 KIS 공식 `open-trading-api` 샘플을 기준으로 고정한다. 공식 샘플이 바뀌면 계약 테스트를 먼저 수정하고 실제 수신 프레임으로 재검증한다.

## 4. 판단 입력

- KIS 잔고의 평균 체결가와 매도가능수량
- NXT 최신 체결가, 체결강도, 매수·매도 체결 건수
- NXT 최우선·전체 매수/매도 잔량
- KRX 예상 시초가
- 시장 위험 상태와 시장 스트레스 점수
- 최신 수신 시각과 NXT 최소 표본 수

뉴스·토론·외부 LLM 응답은 이 실시간 주문 경로의 입력으로 사용하지 않는다.

## 5. 결정 규칙

```text
if 데이터가 부족하거나 오래됨:
    HOLD + 신규매수 차단
elif NXT 또는 KRX 예상가 기준 평균체결가 대비 수익률 <= -7%:
    HARD_STOP 전량매도 계획
elif KRX 예상 수익률 <= -5%
     and NXT도 -3% 이하
     and (NXT 매도압력 or 시장 스트레스 or RISK_OFF):
    STRONG_DEFENSE 전량매도 계획
elif KRX 예상 수익률 <= -3%
     and NXT도 -3% 이하
     and (NXT 매도압력 or 시장 스트레스 or RISK_OFF):
    EARLY_DEFENSE 전량매도 계획
else:
    HOLD
```

초기 `-3%·-5%` 및 압력 임계값은 모의 개선판 실험값이다. `-7%`만 불변 규칙이며, 나머지는 모의 성과와 오탐률을 검증한 뒤 사용자 승인으로 승격한다.

## 6. 장애와 재시작

- NXT 미지원 종목, 수신 단절, 표본 부족, 오래된 예상체결가는 매도 근거로 추정하지 않는다.
- 데이터가 부족하면 신규매수는 차단하되 기존 장중 보호 감시는 계속한다.
- 잠긴 계획에는 종목, 포지션 세대, 수량, 정책 버전, 판단 사유, 거래일을 기록한다.
- 09시 직전 또는 직후 재시작하면 KIS 잔고·미체결 주문을 먼저 대조한다.
- 같은 `(symbol, generation, reason, policy_version)` 계획은 기존 멱등성 키를 통해 중복 주문을 막는다.

## 7. 완료 조건

로컬 구현 완료와 실제 운용 검증 완료를 구분한다.

- 자동 테스트: NXT/KRX 프레임 파싱, 다종목 분리, 데이터 부족, `-3/-5/-7%`, 시간 게이트, 만료, 매수권한 부재
- 실제 KIS 모의 검증: 08시 NXT 수신, 08시 30분 KRX 예상체결 수신, 09시 계획 전달, 주문·체결·잔고 대조
- 장애 검증: WebSocket 재연결, 08:50/09:00 재시작, 예상체결 누락, NXT 미지원 종목, 중복 실행

실제 KIS 모의 장전 세션과 다음 정규장 검증 증거가 없으면 상태는 `BLOCKED`이며 실전 주문 기능으로 승격하지 않는다.
